## 📖 About the Project

**Airline Cloud Testing & Bug Reporting** is a software quality assurance project focused on testing airline website functionalities through the cloud-based testing platform **LambdaTest**.

The project aims to evaluate the functionality, usability, and browser compatibility of airline web application workflows. It involves executing test scenarios, observing application behavior, identifying unexpected results, and documenting defects in a structured format.

By leveraging cloud-based browser testing, the project explores how web applications can be validated across different browser environments without depending entirely on locally installed browsers.

### 🎯 Problem Statement

Airline websites provide several interconnected services, including flight searches, booking-related interactions, passenger information forms, and navigation between different pages.

Unexpected application behavior or browser-specific issues can negatively affect the user experience.

This project addresses these challenges through systematic functional validation, cross-browser testing, and structured defect reporting.

## 🧪 Testing Scope

The testing process can cover the following airline website modules, depending on the application's available functionality.

| Module | Test Scenarios |
|---|---|
| Homepage | Page loading, navigation, and interface validation |
| Flight Search | Source, destination, and travel-date inputs |
| Search Results | Flight result display and information validation |
| Passenger Details | Form validation and input handling |
| Booking Workflow | Navigation and booking-related interactions |
| Browser Compatibility | UI rendering and functionality across browsers |
| Error Handling | Invalid inputs and unexpected application responses |

### 🔬 Testing Methodologies

**1. Functional Testing**

Verifies whether application features behave according to their specified requirements.

**2. Cross-Browser Testing**

Checks whether the application provides consistent functionality and presentation across supported browsers.

**3. UI Validation**

Examines page layouts, buttons, forms, navigation elements, and visual consistency.

**4. Negative Testing**

Checks how the application responds to invalid, incomplete, or unexpected inputs.

**5. Regression Testing**

Rechecks previously tested functionalities after changes to ensure existing behavior has not been affected.

## 🐛 Bug Reporting & Defect Documentation

An important part of this project is documenting identified defects in a structured and reproducible manner.

Each defect report should contain:

| Field | Description |
|---|---|
| Bug ID | Unique defect identification number |
| Bug Title | Short description of the issue |
| Module | Application section where the issue occurs |
| Steps to Reproduce | Actions required to reproduce the defect |
| Expected Result | Correct expected application behavior |
| Actual Result | Behavior observed during testing |
| Severity | Impact of the defect |
| Status | Open, In Progress, Fixed, or Retested |

### Example Bug Report

**Bug ID:** BUG-001

**Title:** Flight Search Form Accepts Incomplete Input

**Module:** Flight Search

**Steps to Reproduce:**
1. Open the airline website.
2. Navigate to the flight search section.
3. Leave a mandatory field empty.
4. Attempt to submit the form.

**Expected Result:** The application should display an appropriate validation message.

**Actual Result:** Record the behavior observed during testing.

**Severity:** To be assigned based on actual impact.

**Status:** As per testing observation.
